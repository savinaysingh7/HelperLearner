# HelperLearner User Manual

## 1. Purpose
This manual explains how a normal user should use HelperLearner to post requests, solve problems, manage jobs, and collaborate with others.

## 2. User Roles
HelperLearner supports several user types:

- Requesters who need help with coding problems.
- Helpers who solve requests and earn KP.
- Clients who post freelance jobs and fund milestones.
- Contractors who apply for jobs and deliver work.
- Workspace members who collaborate on issues and sprints.

## 3. Getting Started
### 3.1 Sign Up
Create an account using the registration flow. After logging in, complete your profile with a bio, skills, and relevant details.

![Login Page — Enter your username and password to access the platform](screenshots/login_page.png)

### 3.2 Update Profile
Keep your profile current so the matching and trust systems can surface you appropriately.

### 3.3 Understand Your Wallets
HelperLearner tracks both Knowledge Points and INR balances. KP is used internally, while INR is used for paid work and wallet transactions.

After logging in, you will see the home dashboard with platform stats, recent requests, and recent paid jobs:

![Home Dashboard — View platform statistics, recent help requests, and recent paid jobs at a glance](screenshots/home_page.png)

## 4. Using Help Requests

![Browse Help Requests — Filter by keyword, skill, and tag to find requests matching your expertise](screenshots/browse_requests.png)

### 4.1 Create a Help Request
1. Open the help request form.
2. Describe the issue clearly.
3. Set the KP bounty.
4. Submit the request.

### 4.2 Claim and Solve
Helpers can claim available requests, post solutions, and receive KP when the request is accepted.

### 4.3 Rate the Outcome
After a request is solved, the requester can leave a rating and feedback to improve trust scoring.

## 5. Using Freelance Jobs

![Freelance Jobs — Browse paid opportunities with INR budgets, escrow balances, and skill requirements](screenshots/freelance_jobs.png)

### 5.1 Post a Job
Clients can create a job description, budget, deadline, and milestone structure.

### 5.2 Apply for a Job
Contractors can submit proposals, explain their approach, and negotiate the work.

### 5.3 Fund and Deliver
Once a proposal is accepted, milestones are funded and tracked. The job can then move through delivery and approval stages.

## 6. Workspaces
Workspaces help teams manage coding tasks in a structured way.

- Create or join a workspace.
- Add issues and organize them on a board.
- Track work through sprints.
- Use chat to coordinate changes.

## 7. Real-Time Chat
Chat is used for fast communication around help requests, jobs, and workspace tasks. Messages update in near real time, which reduces delays and keeps discussions in context.

## 8. Search
Use the search tools to find:

- Requests by keywords or difficulty.
- Jobs by technology, budget, or deadline.
- Users by skills or trust score.
- Workspace issues and discussions.

## 9. Notifications
Notifications are sent for important events such as:

- New messages.
- Request claims.
- Job proposals.
- Milestone approvals.
- Payment updates.

Users can usually control notification preferences from their profile settings.

## 10. Trust and Safety
To keep the platform reliable:

- Complete your profile fully.
- Avoid spam or duplicate posts.
- Communicate clearly.
- Deliver on time.
- Follow platform rules and moderation guidance.

Trust scores are used to help highlight dependable users and reduce abuse.

## 11. Common Workflows
### 11.1 Ask for Help
1. Sign in.
2. Create a help request.
3. Wait for helpers to respond.
4. Review solutions.
5. Accept the best one.

### 11.2 Offer Help
1. Browse requests.
2. Choose one that matches your skills.
3. Claim it if allowed.
4. Post a solution.
5. Wait for feedback and KP reward.

### 11.3 Hire for a Job
1. Create a job post.
2. Review proposals.
3. Pick a contractor.
4. Fund the milestone.
5. Approve delivery when complete.

## 12. Best Practices
- Write clear titles and descriptions.
- Attach useful context, logs, or screenshots when needed.
- Keep communication inside the platform where possible.
- Review trust signals before accepting proposals or solutions.
- Close completed items promptly.

## 13. Troubleshooting
### 13.1 I cannot log in
Check your credentials, verify the account exists, and reset your password if needed.

### 13.2 My request is not getting replies
Improve the description, add tags or skills, and make the bounty clear.

### 13.3 My payment is pending
Review the milestone or escrow status and confirm whether approval is still required.

## 14. Support
If something does not work as expected, use the issue or support flow defined by the project maintainers.
